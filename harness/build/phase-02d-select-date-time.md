# Phase02d — Consistent select, date and time controls

User 17/10/2026 reports native browser select menus and date/time popups look disconnected from the application. Replace all visible selects and date/time pickers across admin filters, classes, account/manager assignment, registration intake/transfer/payment, student profile and public signup. Keep existing role/roster/payment and ISO payload rules.

Use shared shadcn-style Radix Select and Popover wrappers from installed radix-ui1.8.1, no second UI framework. Application SelectField/SelectOption handle empty values and consistent sizing/focus/portal placement. Use explicit value callbacks and RHF Controller rather than faking native events. Preserve real form names/default values through Radix form controls. Label triggers by id or explicit accessible name; keyboard/typeahead/Escape/focus return and nested dialog interaction must work.

Dependency proposal before installation: @daypicker/react10.0.2 MIT, official current React DayPicker. New dependency, not an upgrade of an existing date library. Compatible React>=16.8 including current19.2/Next16.3/Node22. Existing stack has no calendar; add only the library needed for a localized accessible grid/keyboard/month navigation, not a second form/state framework. date-fns/@date-fns/tz are its internal runtime dependencies; do not add extra direct dependencies. Import Vietnamese locale, restrict client code to controls that use the calendar. Native month/year dropdowns are replaced by the same shared styled select. Date field supports typed dd/mm/yyyy; time supports HH:mm24-hour; datetime supports both. Parse strictly, retain invalid typed draft/error instead of silently choosing a different day; submit only original ISO date/time formats. Handle leap dates, bounds, clearing, required and form reset. Avoid timezone shifts for date-only values. No DB migration.

Sources: https://daypicker.dev/ ; https://ui.shadcn.com/docs/components/radix/select ; https://ui.shadcn.com/docs/components/radix/date-picker ; https://www.radix-ui.com/primitives/docs/components/popover . Installed Next server/client guide read before changes.

Risks/tests: popup portal clipping/stacking, RHF state and FormData, empty selections, dependent filters, long options, mobile widths360/390, dropdown inside dialogs, focus return/Escape, Vietnamese calendar navigation and keyboard, typed/calendar leap-date conversion, time/datetime round trips. Update existing Playwright interactions to use actual visible styled controls, never select hidden form elements. Type/lint/build, relevant existing workflows and dedicated UI checks. Rollback only this phase source/dependency changes; retain prior dirty work/data. No container deployment implied. Status: implemented and verified locally.
